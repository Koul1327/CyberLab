# Обход аутентификации

## Причина уязвимости

Обработчик /login получал пароль из формы ввода, но не проверял его. Он сразу создавал сессию и назначал роль admin, если введенное имя было admin. Поэтому юзер мог получить доступ рута с любым паролем.

## Как воспроизвести

1. В уязвимой версии отправить форму `/login` с именем `/admin` и заведомо неверным паролем
2. С полученной сессии открыть `/admin`
3. Убедиться, что админка доступна: сервер возвращает 200 и показывает админку

## Исправление

Сервер теперь ищет пользователя в словаре users. Если аккаунт не найден или введенный пароль не проходит проверку сохраненного хэша, вход отклоняется. После успешной проверки имя и роль записываются в сессию. Роль берется из учетки пользователя.

## Что проверяют тесты

- Неверный пароль отклоняется, имя и роль не появляюьтся в новой сессии
- Alex с правильным паролем получает сессию с ролью user
- Вошедщий Alex не может открыть /admin
- Admin с правильным паролем получает доступ к /admin
- Уязвимая версия выдает админку с неверным паролем
- Исправленная версия отклоняет такую попытку
