# SQL-injection - подмена условия поиска

## Причина Уязвимости

Уязвимая версия вставляла ввод юзера прямо в SQL через f-строку, а она позволяет подменить структуру запроса

## Исправление

Исправленная версия использует параметризированный запрос, то есть ввод передается отдельно и обрабатывается как значение, а не SQL-код

## Воспроизведение

Команды выполняются из корня cyberlab с активынм окружением:

```bash
source .venv/bin/activate
```

### Уязвимая версия

```bash
python3 -m flask --app labs.sql_injection.vulnerable.app run --host 127.0.0.1 --port 5000
```

Открыв другой терминал можно проверить обычный поиск:

```bash
curl -G --data-urlencode "name=Mouse" http://127.0.0.1:5000/search
```

Видим один товар

Затем применяем SQL-иньекцию:

```bash
curl -G --data-urlencode "name=' OR 1=1 -- " http://127.0.0.1:5000/search
```

Видим все 3 товара

### Исправленная версия

В другом терминале с активынм окружением пишем:

```bash
python -m flask --app labs.sql_injection.fixed.app run --host 127.0.0.1 --port 5007
```

Повтори оба запроса:

```bash
curl -G --data-urlencode "name=Mouse" http://127.0.0.1:5007/search
curl -G --data-urlencode "name=' OR 1=1 -- " http://127.0.0.1:5007/search
```

Обычный поиск возвращает Mouse. Ввод с SQL-инъекцией возвращает:

```json
{"products": []}
```

Он обрабатывается как буквальное название товара, которого нет в базе

## Тесты

```bash
python -m pytest labs/sql_injection/tests/ -q
```

Ожидаем: 3 passed.

Проверяются три сценария:

- SQL-инъекция возвращает все товары в уязвимой версии
- Исправленная версия возвращает пустой список для того же ввода
- Обычный поиск продолжает возвращать нужный товар
