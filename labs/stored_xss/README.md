# Stored XSS - сохраненный код в комментариях

## Причина уязвимости

Сервер созранял комментарий и вставлял его в HTML без экранирования. Браузер воспринимал содержание коммента как часть страницы, поэтому сохраненный JS выполнялся при ее просмотре

## Воспроизведение

Команды выполняются из корня cyberlab с активным окружением

Запуск уязвимой версии:

```bash
python3 -m flask --app labs.stored_xss.vulnerable.app run --host 127.0.0.1 --port 5000
```
1. Открыть 127.0.0.1:5000/
2. Написать текст:

```html
<script>alert("Hello world")</script>
```
3. Убедится, что появилось окно с надписью 'Hello world'
4. Открыть этот же адрес в новой вкладке без повторной отправки формы, и окно появится снова, комментарий сохранен на сервере

## Исправление

Комментарии передается в HTML-шаблон через `render-template'
Jinja сама экранирует ввод при выводе через '{{ comment }}' в данном HTML-текстовом контексте

Исходник сохраняется, но браузер отображает его как текст

Запуск исправленной версии:

```bash
python -m flask --app labs.stored_xss.fixed.app run --host 127.0.0.1 --port 5000
```

Открыть http://127.0.0.1:5000/ и повторить отправку
Комментарий должен отображаться текстом без выполнения JavaScript

## Тесты

```bash
python -m pytest labs/stored_xss/tests/ -q
```

Три теста проверяют:

- сохранённый скрипт попадает в HTML уязвимой версии без экранирования
- исправленная версия возвращает экранированный текст
- обычный комментарий сохраняется и доступен другому юзеру
